🚀 PROYECTO DE INGENIERÍA & DESARROLLO DE API RESTFUL (v2.0)

UEFA Champions League Historical Archive API & SuperAdmin Dashboard

Este sistema fue diseñado y construido desde cero como un proyecto integral de Desarrollo de una API RESTful Profesional con arquitectura de datos relacional, transacciones atómicas, seguridad de doble factor (2FA), caché de alto rendimiento, documentación OpenAPI 3.0 y un panel web interactivo de administración.

🛠️ Lenguajes, Motores y Herramientas Utilizadas (¿En qué se usó cada tecnología?)

Especificación técnica de cada componente que hace funcionar la API y el Panel SuperAdmin:

🟦

TypeScript (TS v7 / tsx)

Lenguaje Principal del Backend

¿En qué se usó?: Todo el código fuente del servidor (carpeta src/) está escrito en TypeScript con tipado estático estricto. Se utilizó para tipar las peticiones y respuestas HTTP (Request, Response, AuthRequest), los middlewares de seguridad, la configuración de Swagger y las consultas a base de datos, evitando errores en tiempo de ejecución mediante validación con npx tsc --noEmit.

🟩

Node.js & Express.js (v5)

Motor y Framework de la API REST

¿En qué se usó?: Construcción del servidor HTTP y la arquitectura modular de endpoints bajo el prefijo /api/v1. Divide limpiamente las rutas públicas de lectura (public.routes.ts) de las rutas protegidas de escritura (admin.routes.ts), gestiona políticas CORS, parseo JSON y sirve los archivos estáticos del panel en /admin.

🐘

PostgreSQL (ucl_archive)

Base de Datos Relacional SQL

¿En qué se usó?: Motor de persistencia relacional donde se almacenan las 7 entidades del sistema (Season, Phase, Club, Player, SquadMember, Match y MatchEvent). Garantiza integridad referencial mediante llaves foráneas (Foreign Keys), índices únicos (ej: nombres de clubes y años de temporada) y borrado en cascada (onDelete: Cascade).

💎

Prisma ORM (@prisma/client)

Modelado, Migraciones y Transacciones

¿En qué se usó?: Definición del esquema de datos en prisma/schema.prisma, Enums oficiales (TournamentFormat, PhaseCode, SquadRole, MatchStatus, EventType) y ejecución de transacciones atómicas (prisma.$transaction) para generar automáticamente las fases al crear una temporada y actualizar los goles históricos (+1) de los jugadores al registrar partidos e incidencias.

⚡

Thunder Client (VS Code)

Pruebas HTTP y Auditoría de Endpoints

¿En qué se usó?: Herramienta clave durante el desarrollo de la API para probar manualmente cada endpoint (GET, POST, PUT, DELETE), auditar tiempos de respuesta, validar la autenticación enviando el encabezado Authorization: Bearer <token>, comprobar validaciones de errores (400, 401, 403, 404) y verificar la estructura de los JSON.

🔐

JWT (jsonwebtoken) & Nodemailer

Seguridad 2FA por Correo y Roles

¿En qué se usó?: Implementación del sistema de autenticación en dos pasos (2FA) en mail.service.ts y auth.middleware.ts. Valida correo y contraseña maestra, envía un código OTP único de 6 dígitos por SMTP Gmail y firma tokens JWT distinguiendo entre el rol SUPERADMIN (control total) y EDITOR (colaborador sin permiso de vaciar la base de datos).

🚀

Redis (ioredis) & Express Rate Limit

Caché en Memoria y Protección DDoS

¿En qué se usó?: En cache.middleware.ts se almacena en caché el resultado de los endpoints públicos para responder en milisegundos, limpiando el caché automáticamente cuando el SuperAdmin inserta o edita datos (con respaldo en RAM si Redis no está activo). En rateLimit.middleware.ts protege el login y la API contra ataques de fuerza bruta por IP.

📖

Swagger UI & OpenAPI 3.0

Documentación Interactiva Oficial

¿En qué se usó?: Configurado en src/config/swagger.ts para exponer en la ruta /api-docs el catálogo interactivo de todos los endpoints de la API, permitiendo visualizar los esquemas de entrada/salida y ejecutar peticiones de prueba directamente desde el navegador.

📸

Multer (Multipart Upload)

Subida de Escudos y Fotografías

¿En qué se usó?: Configurado en src/middlewares/upload.middleware.ts para procesar archivos de imagen subidos desde la PC en POST /api/v1/upload, validando extensiones permitidas (PNG, JPG, WEBP, SVG) y almacenándolos de forma organizada en public/uploads/clubs y public/uploads/players.

🎨

HTML5, CSS3 & JavaScript (ES6+ Fetch)

Frontend del SuperAdmin Dashboard

¿En qué se usó?: Desarrollo de este panel interactivo en public/admin/ (index.html, styles.css, app.js). Conecta en vivo con la API mediante fetch() asíncrono, filtra las 55 federaciones de la UEFA por región geográfica, previsualiza imágenes al instante y permite gestionar temporadas, plantillas y partidos de forma 100% visual.

🟢

Neon.tech (Serverless PostgreSQL)

Base de Datos Cloud en Producción

¿En qué se usó?: Alojamiento en la nube (AWS US East Ohio) de la base de datos PostgreSQL de producción (neondb) con Connection Pooling y cifrado SSL. Permite que todos los datos registrados por los SuperAdmins persistan de forma segura y compartida en internet 24/7.

☁️

Render.com & GitHub CI/CD

Despliegue Cloud y Servidor en Vivo

¿En qué se usó?: Plataforma Cloud (PaaS) conectada directamente al repositorio oficial de GitHub (Nicomszws12/UCL-Archive-API). Automatiza el despliegue continuo (CI/CD) ejecutando npm install && npx prisma generate && npx prisma db push y manteniendo en línea tanto la API como el panel SuperAdmin y Swagger UI.

⏱️

Cron-job.org & Auto-Ping (Keep-Alive)

Disponibilidad 24/7 Sin Inactividad

¿En qué se usó?: Programación de tareas automatizadas (Cronjobs) y rutina interna en src/index.ts que envían peticiones periódicas al endpoint de salud GET /api/v1/health cada 10–12 minutos. Evita que la instancia gratuita de Render entre en suspensión por inactividad, garantizando respuesta inmediata 24/7.

📨

Google Apps Script (MailApp HTTPS)

Puente de Correo 2FA por Puerto 443

¿En qué se usó?: Microservicio Serverless en Google Cloud conectado vía Webhook HTTPS (GOOGLE_SCRIPT_URL) en src/services/mail.service.ts. Permite despachar los correos con el código OTP de 6 dígitos en tiempo real desde servidores en la nube donde los puertos SMTP tradicionales (25/465/587) están restringidos.

🌍

App Cliente (/app) & API Keys (x-api-key)

Demostración de Consumo Externo

¿En qué se usó?: Aplicación web consumidora en public/app/index.html que demuestra cómo un sistema externo consume la API REST mediante llaves x-api-key, generando fragmentos de código listos para JavaScript (fetch), Python (requests) y cURL, junto con un inspector de respuestas JSON en vivo.

🐙

Git & GitHub (Control de Versiones)

Repositorio Colaborativo y Seguridad

¿En qué se usó?: Gestión del historial de commits del proyecto en github.com/Nicomszws12/UCL-Archive-API, trabajo colaborativo entre ambos SuperAdmins, protección de variables sensibles con .gitignore / .env.example y disparo automático de despliegues hacia Render.
